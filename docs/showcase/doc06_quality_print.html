PostgreSQL Case Study • Section 05
05 — Defect Case Study

Case Study: The PostgreSQL Animal Search Defect

How a subtle SQL parameter deduction defect was identified, diagnosed, solved via Criteria API, and permanently shielded.

1. Root Cause Analysis

In PostgreSQL, static JPQL queries containing nullable enum expressions like (:species IS NULL OR a.species = :species) caused Hibernate to bind null with Types.VARBINARY or bytea. When executed against RDS PostgreSQL 15, the query planner threw PSQLException: could not determine data type of parameter $1.

2. JPA Criteria API Resolution

Replaced static JPQL with AnimalSpecification utilizing dynamic JPA Criteria API predicates. Null parameters are omitted entirely from the generated SQL WHERE clause, eliminating type inference ambiguity and producing clean index-optimized SQL.

Fault Tolerance • Section 07
07 — Resilience Architecture

Resilience4j Circuit Breakers, Retries & Controlled Failover

Protecting system integrity against external AI gateway drops and transient database spikes.

1. Circuit Breakers

Resilience4j circuit breakers monitor external Gemini API latency. When the failure rate exceeds 50% across a 10-call sliding window, the circuit trips to OPEN to prevent thread starvation.

2. Exponential Backoff

Transient database connection blips and HTTP 503 gateway drops trigger bounded exponential backoff with randomized jitter to prevent server thundering herds.

3. Multi-Agent Failover

FailoverManager routes requests automatically to backup heuristic rule engines when primary LLM inference times out, ensuring veterinary operations continue uninterrupted.
