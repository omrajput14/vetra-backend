01 — Field Product Context

The Role of Mobile in Veterinary Field Operations

The mobile application is the primary execution interface connecting rural farmers and field veterinarians with the cloud core.

"In agrarian livestock healthcare, desktop web applications fail because veterinarians do not operate in offices—they work in remote barns, cattle sheds, and rural farms with volatile 4G network connectivity. Vetra Mobile was engineered not as a decorative frontend, but as an operational field instrument providing cryptographic identity, QR animal passports, appointment coordination, and real-time disease surveillance directly in the field."

— Om Rajput, System Architect
1. Smallholder Farmer Workflow

- Animal Passports: Register cattle, buffalo, sheep, and goats with digital ear tags and QR passports.
- Appointment Booking: Find nearby verified veterinarians and schedule clinical consultations.
- Outbreak Alerts: Receive localized spatial biosecurity warnings within a 50km radius.

2. Licensed Veterinarian Workflow

- QR Scanner Verification: Instant barcode lookup of full longitudinal medical histories.
- Clinical Records (EVMR): Record clinical diagnoses, prescribe medications, and calculate drug withdrawal periods.
- Disease Surveillance: Confirm active disease reports with GPS coordinates for regional epidemiological tracking.

06 — Mobile Security

Client-Side Security & Credential Sanitization

Hardware-backed keystore persistence and automated debug log sanitization.

1. FlutterSecureStorage Encryption

- iOS: Tokens and user roles are stored in the hardware-backed Apple Keychain.
- Android: Tokens are encrypted via AES-GCM / RSA using the Android Keystore system.
- Zero SharedPrefs: Sensitive credentials never touch unencrypted SharedPreferences.

2. Sanitized Network Logging

- SanitizedLogInterceptor strips headers: Authorization, Cookie, X-Auth-Token.
- Redacts JSON keys: password, accessToken, refreshToken, jwt, secret.
- Prevents credential leakage into device logcats or telemetry.

07 — Resilience Engineering

Bounded Exponential Backoff with Randomized Jitter

Preventing thundering herd problems on rural networks through intelligent retry policies.

Exponential Backoff Mathematical Formula

Delay(n) = min(BaseDelay × 2n-1 + Jitter(0, 100ms), MaxDelay)

- Attempt 1: 500ms + random jitter
- Attempt 2: 1000ms + random jitter
- Attempt 3: 2000ms + random jitter (Ceiling: 3000ms).

Selective Idempotency Policy

- Automatically Retried: GET, HEAD, OPTIONS, and requests with retryable: true.
- Never Blindly Retried: POST / PATCH state mutations (e.g. creating medical records, booking appointments) to prevent duplicate transactions.

10 — Architectural Rigor

Key Mobile Engineering Decisions & Rationales

Technical trade-offs and engineering reasoning behind the mobile implementation.

Decision Problem & Technical Rationale Engineering Benefit
Flutter over React Native Direct compilation to native ARM64 with Skia/Impeller graphics engine for consistent rendering on budget Android devices. Predictable 60 FPS performance, fast startup times, and deterministic UI layouts across heterogeneous rural hardware.
Dio over http package Standard http lacks native support for interceptor chaining, request cancellation, and connection pooling. Enables clean modular separation between AuthInterceptor, RetryInterceptor, and sanitized logging.
Completer Mutex for 401 Multiple simultaneous API calls during token expiry cause duplicate refresh token calls, breaking single-use token rotation. Queues all concurrent requests behind a single refresh flight, replaying them seamlessly with zero user interruption.
Randomized Retry Jitter Fixed interval retries cause synchronized thundering herds when network reconnects in rural areas. Spreads server reconnection traffic evenly across time, protecting backend ALB targets from traffic spikes.
