System Engineering • Section 01
01 — Core System Role

Backend Engineering Overview

The central coordination engine governing clinical records, authentication invariants, spatial surveillance, and transactional boundaries.

Core Backend Responsibilities

1. Deterministic Business Invariants: Enforcing state machine transitions for appointments and immutable EVMR medical history.
2. Zero-Trust Identity: Stateless HMAC-SHA512 JWT verification, cryptographic refresh rotation, and tenant scoping.
3. Geospatial Surveillance: Executing PostGIS spatial queries (ST_DWithin) for real-time outbreak clustering.

Execution Context

The backend runs as containerized tasks on AWS ECS Fargate within private VPC subnets. It exposes versioned RESTful APIs (/api/v1) behind an AWS Application Load Balancer terminating TLS 1.3 on port 443 with automatic HTTP port 80 redirect.

Figure 1.1: High-Level End-to-End Vetra Backend Execution Architecture
Contract Immutability Guarantee

Every API response is encapsulated in a strongly typed ApiResponse<T> envelope. If a business violation occurs, a typed BaseDomainException triggers the GlobalExceptionHandler, ensuring consistent RFC 7807 error structures with zero unhandled stack traces leaked to clients.

Security Design • Section 05
05 — Security Internals

Authentication & Security Filter Chain

Stateless cryptographic JWT authentication, BCrypt password hashing, and Spring Security 6 FilterChain architecture.

SecurityFilterChain Configuration

- CSRF: Explicitly disabled (AbstractHttpConfigurer::disable) as the REST API is purely stateless.
- Session Creation: SessionCreationPolicy.STATELESS (no HttpSession).
- Password Encoder: BCryptPasswordEncoder (strength 12).
- Exception Entry Point: CustomAuthenticationEntryPoint formatting 401 Unauthorized errors as JSON envelopes.

Access Token (JWT) Anatomy

- Algorithm: HMAC-SHA512 via JJWT 0.12.6.
- Subject (sub): User email address.
- Custom Claims: userId (UUID), role (ROLE_FARMER | ROLE_VETERINARIAN).
- Expiration: Configured in JwtProperties (default: 86,400s / 24 hours).

Figure 5.1: Spring Security 6 Stateless JWT Filter Chain & Principal Population Flow
Public Endpoint Whitelist

Configured in SecurityConfig.PUBLIC_ENDPOINTS: /api/v1/auth/farmer/register, /api/v1/auth/farmer/login, /api/v1/auth/vet/register, /api/v1/auth/vet/login, /api/v1/auth/refresh, /api/v1/auth/logout, /actuator/health/**, and /v3/api-docs/**. All other paths require authenticated bearer tokens.

Refresh & Revocation • Section 06
06 — Token Governance

Refresh Token Rotation & Revocation Engine

Single-use cryptographically random refresh token rotation and database-backed session termination.

Refresh Token Schema (refresh_tokens)

- Token Value: Cryptographically secure 256-bit random UUID string.
- State Flags: revoked (BOOLEAN), expiry_date (TIMESTAMP).
- Entity Link: Belongs to User (user_id foreign key).
- Rotation Invariant: When consumed, the old token is marked revoked and a fresh token is issued.

Revocation & Logout Invariant

Calling POST /api/v1/auth/logout sets revoked = TRUE on the active refresh token. Subsequent attempts to rotate with that token fail immediately with HTTP 401 Unauthorized, terminating compromised sessions.

Figure 6.1: Refresh Token Single-Use Rotation & Database State Transition Flow
Mobile Token Desynchronization Prevention

In the Flutter client, AuthInterceptor wraps token refresh calls behind an asynchronous Completer mutex queue. When multiple concurrent requests encounter 401 Unauthorized, only the first triggers POST /api/v1/auth/refresh; all other queued requests await the single rotation result and replay transparently.

Security & RBAC • Section 07
07 — Authorization

Multi-Tenant Isolation & Role-Based Access

Principal-based SQL predicate scoping and Spring Security declarative method authorization.

Role-Based Access Control (RBAC)

- ROLE_FARMER: Register animals, book clinical appointments, view own herd passports and medical history.
- ROLE_VETERINARIAN: Accept appointments, record immutable clinical EVMR entries, issue prescriptions, and submit disease reports.
- Enforcement: @EnableMethodSecurity(prePostEnabled = true) with @PreAuthorize guards on controllers.

Tenant Data Isolation Principle

Data queries never rely on client-supplied farmer IDs in request bodies. The backend extracts the authenticated userId from SecurityContextHolder and injects it into JPA Criteria Predicates (farmer.id = :farmerId). Cross-tenant queries return empty result sets rather than unauthorized data.

Figure 7.1: Multi-Tenant Query Scoping and Role-Based Authorization Engine
Unauthorized Resource Access Handling

If an authenticated farmer attempts to access an animal or record belonging to another tenant (animal.getFarmer().getId() != principal.getId()), the service immediately throws UnauthorizedResourceAccessException which maps to HTTP 403 Forbidden.

Clinical Workflows • Section 10
10 — State Management

REST API: Appointments & State Machine

Clinical appointment booking lifecycle, status state machine, and optimistic locking concurrency control.

Appointment State Machine Invariants

- REQUESTED: Farmer creates visit request for an animal.
- CONFIRMED: Veterinarian accepts and schedules date/time.
- IN_PROGRESS: Clinical triage underway at farm/clinic.
- COMPLETED: Finalized upon creation of medical record.
- CANCELLED: Allowed only from REQUESTED or CONFIRMED.

Optimistic Locking Concurrency Control

Appointment entities include a @Version Long version column. If a farmer cancels while a veterinarian confirms simultaneously, Hibernate throws OptimisticLockingFailureException, caught by GlobalExceptionHandler as HTTP 409 Conflict.

REST API: Immutable Medical Records (EVMR)

Clinical Record Invariants

JPA Criteria Engine • Section 13
13 — Dynamic Query Engine

Dynamic JPA Criteria API & Specifications

How AnimalSpecification.java solved PostgreSQL prepared statement parameter deduction failures.

The Legacy Static JPQL Failure

A static JPQL query (:species IS NULL OR a.species = :species) produced PSQLException: could not determine data type of parameter $X on PostgreSQL RDS when optional enum or UUID parameters were null.

The Dynamic Criteria Solution

Using JpaSpecificationExecutor, AnimalSpecification builds predicates dynamically at runtime. If a search filter is null or blank, no predicate is added, generating clean SQL with 0 untyped parameters.

Source Code: AnimalSpecification.java Implementation
public class AnimalSpecification { public static Specification<Animal> filterAnimals( UUID farmerId, String tagNumber, Species species, AnimalGender gender, String name, String breed) { return (Root<Animal> root, CriteriaQuery<?> query, CriteriaBuilder cb) -> { List<Predicate> predicates = new ArrayList<>(); // Mandatory multi-tenant isolation predicate if (farmerId != null) { predicates.add(cb.equal(root.get("farmer").get("id"), farmerId)); } predicates.add(cb.equal(root.get("isDeleted"), false)); // Dynamic optional predicates — appended ONLY when non-null if (tagNumber != null && !tagNumber.trim().isEmpty()) { predicates.add(cb.like(cb.lower(root.get("tagNumber")), "%" + tagNumber.trim().toLowerCase() + "%")); } if (species != null) { predicates.add(cb.equal(root.get("species"), species)); } if (gender != null) { predicates.add(cb.equal(root.get("gender"), gender)); } if (name != null && !name.trim().isEmpty()) { predicates.add(cb.like(cb.lower(root.get("name")), "%" + name.trim().toLowerCase() + "%")); } return cb.and(predicates.toArray(new Predicate[0])); }; } }
Compile-Time Type Safety

Criteria API provides compile-time checking of entity attributes, eliminating runtime SQL syntax errors and enabling seamless schema refactoring across domain entities.

Live AWS RDS Staging Verification

Verified live on Amazon RDS PostgreSQL 15.13 across all 6 search permutations: Tag-only, Tag+Species, Tag+Gender, Species+Gender, All filters, and No filters. 100% tests returned 200 OK.

Error Architecture • Section 16
16 — Error Architecture

Exception Handling & Standardized Envelopes

Typed domain exception taxonomy, RFC 7807 problem details alignment, and Micrometer span tagging.

Standardized Response Envelope (ApiResponse<T>)

Every HTTP response conforms to a deterministic schema:
- success (BOOLEAN): Indicates execution status.
- statusCode (INT): Canonical HTTP status code.
- message (STRING): Human-readable status or error summary.
- data (T): Strongly-typed payload (null on errors).
- errors (List<FieldError>): Validation error map.
- timestamp (Instant): ISO-8601 server timestamp.

Domain Exception Hierarchy

- ResourceNotFoundException → HTTP 404 Not Found.
- ConflictException → HTTP 409 Conflict.
- UnauthorizedResourceAccessException → HTTP 403 Forbidden.
- BusinessRuleException → HTTP 422 Unprocessable Entity.
- MethodArgumentNotValidException → HTTP 400 Bad Request.

Standard RFC 7807 Validation Error Envelope
HTTP/1.1 400 Bad Request Content-Type: application/json { "success": false, "statusCode": 400, "message": "Request validation failed", "data": null, "errors": [ { "field": "tagNumber", "message": "Ear tag number cannot be blank" }, { "field": "species", "message": "Species must be one of: CATTLE, BUFFALO, SHEEP, GOAT" } ], "timestamp": "2026-08-16T12:00:00Z" }

Resilience4j • Section 17
17 — Fault Tolerance

Reliability Engineering & Circuit Breakers

Resilience4j 2.4.0 circuit breaker state transitions, timeout thresholds, and graceful fallback execution.

Sliding Window (10 Calls)

Tracks the outcome of the last 10 requests. If failure rate exceeds 50%, circuit transitions from CLOSED to OPEN.

Fast-Fail OPEN State (30s)

In OPEN state, incoming calls fast-fail immediately to fallback providers without hitting degrading external endpoints.

HALF-OPEN Probing (3 Calls)

After 30s, circuit allows 3 canary requests. If all succeed, it transitions back to CLOSED; otherwise returns to OPEN.

Figure 17.1: Resilience4j Circuit Breaker State Transition & Recovery Workflow
Fallback Provider Implementation

When external AI diagnosis or image upload services fail, FailoverManager routes requests to a local rule-based fallback provider, ensuring the client receives a structured response rather than an unhandled 500 error.
